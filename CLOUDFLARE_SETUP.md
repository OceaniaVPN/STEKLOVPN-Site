# Cloudflare: общая сезонная тема STEKLOVPN

Оба Worker используют одну базу D1 с именем `steklovpn-shared`. В обоих Wrangler-конфигах есть одинаковый заполнитель `PUT_D1_DATABASE_ID_HERE`: его нужно заменить на один и тот же ID базы.

## 1. Создать базу D1

В любом из проектов после `npx wrangler login` выполнить:

```bash
npx wrangler d1 create steklovpn-shared --location eeur
```

Сохрани выданный `database_id`. Вставь его вместо `PUT_D1_DATABASE_ID_HERE` в:
- `STEKLOVPN-Site/wrangler.toml`
- `Proxy_sait/wrangler.jsonc`

В обоих файлах должны быть одинаковые `database_name` и `database_id`.

## 2. Создать таблицы

Из корня `STEKLOVPN-Site` выполнить:

```bash
npx wrangler d1 migrations apply steklovpn-shared --remote
```

Это одна общая база; миграцию достаточно применить один раз.

## 3. Задать пароль-секрет в обоих Worker

Из корня каждого проекта отдельно выполнить:

```bash
npx wrangler secret put ADMIN_PASSWORD
npx wrangler secret put SESSION_SECRET
```

CLI попросит ввести значение скрытым вводом. Используй одинаковый новый длинный пароль для обоих Worker. Для SESSION_SECRET создай случайную строку не менее 32 байт и задай одно и то же значение обоим Worker. Не записывай секреты в HTML, JS, Wrangler-конфиг или Git.

Ранее присланный в чате пароль лучше заменить новым, потому что он уже есть в истории переписки.

## 4. Деплой

В каждом репозитории отдельно:

```bash
npx wrangler deploy
```

В итоге:
- админ-профиль доступен по круглой кнопке в шапке обеих страниц;
- сервер проверяет пароль через секреты `ADMIN_PASSWORD` и `SESSION_SECRET`;
- вход использует защищённую HttpOnly cookie;
- смена сезона записывается в D1 и видна обеим страницам;
- посетители получают сезон из D1, а не из localStorage;
- осенью случайным образом выбираются листья или дождь, зимой идёт снег, весной появляются лепестки, летом — солнечные блики.

Пока ID базы и секреты не заданы, API намеренно не сможет авторизовать администратора или сохранять сезон.
